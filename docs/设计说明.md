# PagePull · 页面提取器 —— 设计说明

> 一句话目标：**把"某个文件里的某几页 / 某几张表"变成可交付的图片或文件，一次点击完成。**

---

## 1. 需求拆解

用户原始诉求："可提取 PDF / Word 具体页面 + Excel 具体 sheet 表，提取出的页面可保存为图片或文件。"

拆成四层，任何一层没做好，工具就不可用：

| 层 | 问题 | 本产品的答案 |
| --- | --- | --- |
| **对象层** | 三种格式里"一页"分别是什么？ | 统一抽象成 **Unit**：PDF/Word 页 = `p3`，Excel 工作表 = `s::销售明细` |
| **选择层** | 用户怎么知道自己选的是哪页？ | 缩略图网格 + 页码/表名 + 尺寸信息，双击看大图；支持全选/反选 |
| **产出层** | "图片或文件"具体几种？ | 图片（PNG/JPG，可拼长图）、PDF（原生抽页）、DOCX（页图排版）、XLSX（工作表另存） |
| **批量层** | 一次处理多个文件？ | 文件队列 + 每个文件独立勾选状态 + 一次导出全部 |

**不在范围内**（有意为之）：PDF 编辑/合并/签名、Word 正文编辑、Excel 数据计算、OCR。工具只做"取出来"这一件事。

---

## 2. 核心设计判断

这一节是整个软件的技术骨架，三个判断决定了实现路线。

### 2.1 PDF 有真页面 → 直接搬对象，不要重排

PDF 的页是**排版完成的最终产物**，页边界、字体、图形都是确定的对象。

- 做法：`PyMuPDF` 的 `insert_pdf(src, from_page, to_page)` 把选中页的对象树复制进新文档。
- 收益：**零损失**——矢量文字仍可搜索复制，超链接、注释、书签跟着走；非连续页码（1、3、5）能按用户顺序重排。
- 反例：先渲染成图再合成 PDF，等于自毁画质。除非用户明确要图片，否则永远走这条路（导出格式选 PDF 时即为该路径）。

### 2.2 Word 没有"页" → 借 Office 排版，页码才可信

Word 文档（.docx）里只有段落和字符，**页码是打开后由排版引擎算出来的结果**。三种可选方案：

| 方案 | 原理 | 结论 |
| --- | --- | --- |
| 解析 `w:lastRenderedPageBreak` | 用 Word 上次保存时写入的分页标记 | ✗ 不可靠：只在 Word 渲染并保存过时存在，改一个字就过期 |
| 自己实现排版 | 复刻字体度量与分页规则 | ✗ 不现实，永远追不上 Office |
| **让 Word 自己排版**：导出 PDF，按 PDF 页取 | Word 打印预览的分页 = PDF 的分页 | ✓ **采用**。用户看到的页码就是拿到的页码 |

实现要点：
- `Word.Application` 用 `DispatchEx` 起**独立进程**（不干扰用户已打开的 Word），只读打开、`Repaginate()` 后 `ExportAsFixedFormat`，`finally` 里关文档 → 退进程。
- 转换结果**按 `(路径, 大小, 修改时间)` 缓存**，同一文件反复勾选/导出不再付转换成本；文件一改，缓存键变化自动失效。
- 转换完成后，Word 文件在内部**完全退化为 PdfSource**，缩略图、渲染、抽页全部复用 PDF 那套逻辑——一份代码两种格式。

### 2.3 Excel 也没有"页" → 单位是工作表，成图走打印管线

Excel 的"页面"取决于纸张、缩放、分页符，本质上不稳定；用户的真实单位是**工作表（sheet）**。

渲染成图片有两条路：

| 方案 | 问题 | 结论 |
| --- | --- | --- |
| `Range.CopyPicture` + Chart 导出 | 只能导选区；宽表被裁、分页不可控、样式偶发丢失 | ✗ |
| **工作表复制到临时簿 → `ExportAsFixedFormat` 打印成 PDF → 光栅化** | 依赖 Excel，但分页/缩放/页边距全由 `PageSetup` 控制 | ✓ **采用** |

- 关键设置：`Zoom=False; FitToPagesWide=1; FitToPagesTall=False`，宽表自动缩到**一页宽**，不拦腰截断；横表自动切横向纸张。
- 附带好处：同一管线顺带产出"每表一个 PDF"（多表还能合并）。
- "存为文件"走另一条更保真的路：`Worksheet.Copy()` 到新工作簿再 `SaveAs(51)`，**格式、列宽、合并单元格、公式、图表全部保留**——比任何 Python 库重写单元格都保真。

### 2.4 结论：一条主干 + 三个适配器

```
             ┌──────────────┐
   任意文件 → │  open_source │  按扩展名分派
             └──────┬───────┘
      ┌─────────────┼──────────────┐
      ▼             ▼              ▼
  PdfSource    WordSource      ExcelSource
  原生页面     Office→PDF      工作表→打印PDF
      │         （内部=PDF）         │
      └─────────────┴──────────────┘
                    ▼
        units / thumbnail / render / export_pdf
                    ▼
              ┌──────────┐
              │ exporter │  PNG/JPG · PDF · DOCX · XLSX
              └──────────┘
```

三个来源对外**接口完全一致**，所以界面层、导出层不需要知道文件是什么格式。

## 3. 功能清单

**输入格式**：`.pdf` `.doc` `.docx` `.docm` `.rtf` `.xls` `.xlsx` `.xlsm` `.xlsb`
（Word/Excel 的旧格式由 Office 打开时自动转换）

**选择**
- 缩略图卡片：页/表缩略图 + 标签 + 尺寸或行列数，隐藏工作表标注「隐藏」
- 单击缩略图或勾选框切换；双击按 150 DPI 打开大图
- 全选 / 反选 / 清空选择；≤40 个单位的文件默认全选，长文档默认不选（避免误导出几百页）
- 按文件记忆勾选状态，切来切去不丢

**导出**
- 图片：PNG / JPG，96 / 150 / 200 / 300 / 600 DPI，JPG 质量 50–100
- 长图：所选页纵向拼接成一张（补白居中，间距 14px）
- PDF：原始页对象重组（Excel 则为工作表打印页合并）
- DOCX：A4 纵向、1.2cm 页边距、按可用宽度插图、每个单位另起一页
- XLSX：多表合并为一个工作簿，或一表一文件
- 命名：`前缀 + 原名 + _单位 + 后缀`，非法字符自动替换，重名自动加 `(2)`，可选覆盖/跳过

**交互**
- 拖拽文件或文件夹进窗口（文件夹递归扫描）
- 后台线程解析与渲染，界面不卡；进度条 + 日志
- 记忆上次的格式、DPI、输出目录、前后缀

## 4. 架构与文件职责

```
main.py                  QApplication 引导、全局字体与 QSS、启动时清理过期缓存
ui/
  main_window.py         三栏布局、菜单、拖放、勾选状态机、导出编排与结果反馈
  state.py               DocEntry（运行时状态）+ Loader/Thumbnailer 两个 QThread
  widgets.py             UnitCard（卡片）、PreviewGrid（自适应列数网格）、PreviewDialog（大图）
  theme.py               QSS：卡片、按钮、输入、滚动条、进度条
core/
  models.py              Unit / ExportSpec / Job / SUPPORTED_EXTS
  sources.py             PdfSource / WordSource / ExcelSource + open_source 工厂
  office.py              COM 桥接、缓存、LibreOffice 与 openpyxl 降级、过期清理
  exporter.py            run_jobs：格式分派、命名冲突、长图拼接、DOCX 排版
tools/                   samples 生成、弱网 wheel 下载
tests/                   smoke_test（14 项）、gui_smoke（离屏 UI）
```

### 线程模型

| 线程 | 职责 | 为什么单独 |
| --- | --- | --- |
| 主线程 | 只做界面绘制与事件 | 任何 COM/渲染放主线程都会假死 |
| `Loader`（串行队列） | 打开文件、取单位列表 | Word/Excel 转换是秒级操作，串行最稳 |
| `Thumbnailer`（懒加载队列） | 按需渲染 300px 缩略图 | 500 页文档不能一次性渲染 |
| `ExportWorker` | 跑 `run_jobs` | 导出耗时最长，需要进度回传 |

`office.py` 里有一把模块级 `RLock`：Office COM 是单线程公寓模型，多线程同时驱动 Excel 会互相干扰，所以所有 COM 调用串行化（Python 侧等待，不影响 UI 响应）。

## 5. 导出矩阵

| 来源 | PNG/JPG | PDF | DOCX | XLSX |
| --- | --- | --- | --- | --- |
| **PDF** | `Page.get_pixmap(zoom=dpi/72)` | `insert_pdf` 复制页对象 | 页图按 A4 宽度插入 | 不支持（明确跳过并记日志） |
| **Word** | 同上（内部已是 PDF） | 同上，等效"按页拆 Word" | 同上 | 不支持 |
| **Excel** | 工作表→打印 PDF→光栅化，可多页 | 每表 PDF 合并 | 表图入 DOCX | `Worksheet.Copy` + `SaveAs`；无 Office 时 openpyxl 重建 |

格式与来源不匹配时（例如对 PDF 选 XLSX），导出器**不报错中断**，跳过该文件并在日志说明——批量场景下不应因一个不匹配的任务全盘失败。

## 6. 关键技术细节

**DPI 与缩放**：PDF 用户空间是 72 DPI，`zoom = dpi / 72`。A4（595×842pt）在 200 DPI 下约 1653×2339 px。

**内存**：600 DPI 的 A4 单页 RGB ≈ 4960×7016×3 ≈ 104 MB。长图拼接会同时持有全部页，故对 600 DPI + 长图做了提示性约束（建议 300 DPI 以内），导出逐文件进行并及时释放。

**缩略图**：按目标宽度 300px 反算 zoom，再缩放到 166×218 卡片区，`SmoothTransformation` 保证不锯齿；生成结果按 `(uid, key)` 缓存在 `DocEntry.thumbs`。

**缓存**：`%LOCALAPPDATA%\PagePull\cache\`，键含路径/大小/mtime/参数（如是否一页宽）。启动时清理 72 小时以上的旧文件。

**COM 安全**：`DispatchEx` 独立进程 → `Visible=False`、`DisplayAlerts=0` → 只读打开 → `finally` 关闭文档/工作簿并 `Quit` → `CoUninitialize`。任何一步失败都不影响用户已打开的文件。

**降级策略**

| 缺失能力 | 后果 | 降级行为 |
| --- | --- | --- |
| 无 Word | 无法确定 Word 分页 | 尝试 LibreOffice `--convert-to pdf`；都没有则明确报错并提示安装 |
| 无 Excel | 工作表无法渲染成图 | 缩略图显示「无法预览」；XLSX 导出改走 openpyxl（值+样式+合并+列宽，图表/图片丢失） |
| 无 Office 全部 | — | 纯 PDF 场景完全可用 |

**性能实测**（本机，Office 16 / Python 3.13）：见第 8 节自测输出。首次 Word 转 PDF 1–3 s，之后走缓存 < 100 ms；200 DPI 渲染 A4 一页约 60–120 ms；Excel 单表转 PDF 1–2 s。

设计取舍：

- 导出按钮常驻右下角，任何时候都能看到"已选多少"，避免空导出。

## 9. 已知限制与风险

| 限制 | 原因 | 缓解 |
| --- | --- | --- |
| Word 必须能转 PDF | 分页由 Office 决定 | 检测并提示；LibreOffice 兜底 |
| Excel 出图依赖 Excel | 只有 Excel 的打印引擎与单元格渲染完全一致 | XLSX 导出不依赖 Office；纯取数据可加 CSV 通道 |
| 加密/权限受限 PDF | 未接密码输入 | 后续加密码框与 `authenticate` |
| 超大表格一页宽会缩得很小 | FitToPagesWide=1 的代价 | 可加"按实际大小分页"开关（迭代项） |
| 600 DPI 长图内存峰值高 | 全页驻留内存 | 逐页写入临时 PNG 再拼接（迭代项） |
| .doc/.xls 旧格式 | 需要 Office 转换 | 无 Office 时明确报错 |
| 未做代码签名/安装包 | 当前为脚本分发 | 提供 PyInstaller 打包方案（见下） |

## 10. 打包与分发

```powershell
python -m pip install pyinstaller
pyinstaller --noconfirm --clean --windowed --name PagePull ^
  --icon assets/icon.ico ^
  --hidden-import win32com.client --hidden-import pythoncom ^
  --collect-data pymupdf ^
  main.py
```

产物 `dist/PagePull/PagePull.exe`，约 120–160 MB（PySide6 + MuPDF 占大头）。要点：
- `--windowed` 去掉控制台窗口；
- `pythoncom`/`win32com` 必须显式 hidden-import，否则打包后 COM 调用报 `ModuleNotFound`；
- `--collect-data pymupdf` 带上 MuPDF 的内置字体与资源，否则中文可能渲染异常（本项目 PDF 内容为原文件自带字体，影响主要在新建页）。

## 11. 迭代路线

**v1.1 效率向**
- 页码范围语法：输入 `1-3,7,10-` 直接选中
- 导出预设（"300DPI PNG 到桌面"一键复用）
- 队列拖拽排序、同名文件批量重命名规则

**v1.2 能力向**
- PDF 密码输入、权限校验
- Excel "按实际大小分页"与"仅打印区域"开关
- 扫描版 PDF 的页内文字检索（需要 MuPDF 文本层，不引 OCR）

**v1.3 集成向**
- 命令行/静默模式：`pagepull --in a.pdf --pages 1-3 --to png --dpi 300`
- 右键菜单「用 PagePull 提取」
- 剪贴板直出、直接打印
