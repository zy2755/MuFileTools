## 过程中发现并修复的问题

1. **Excel 多表合并只带出第一张表**：pywin32 动态派发下 `Worksheet.Copy(After=…)` 的关键字参数被
   **静默丢弃**（无报错）。改为位置参数 `Copy(None, target)` 后修复。同类风险点（`Documents.Open`、
   `Workbooks.Open`、`SaveAs`、`ExportAsFixedFormat`）全部改为显式位置参数。
   教训：IDispatch 调用不要混用关键字参数，必须逐参数验证。
2. **缓存键使用内置 `hash()`**：Python 字符串 hash 每次进程启动随机化，跨会话缓存永远失效。
   改为 md5(路径+大小+mtime+参数)。
3. **PyMuPDF 2.0 依赖链**（networkx/numpy/onnxruntime）：本程序只用渲染与抽页接口，
   以 `--no-deps` 安装后验证核心功能不依赖 onnxruntime。
4. 弱网环境（≤0.3 MB/s 且断流）：`tools/fetch_wheels.py` 用 HTTP Range 分片并行 + 续传下载 wheel
   再离线安装，实测把聚合吞吐从 0.26 MB/s 提升到 ~0.9 MB/s。

## 用户反馈问题修复

**双击 run.bat 报 `No module named 'PySide6'`**（2026-10-26）：

- 根因 1：本机有多个 Python（AutoClaw 工具链、D:\Python3.13.15、C:\Python314 等），
  开发时依赖装进了工具链解释器，双击 bat 时 PATH 解析到的却是另一个。
  修复：改用项目自带 `.venv`（由 install.bat 创建、优先从 wheels\ 离线安装），run.bat 只认 `.venv`。
- 根因 2：bat 文件以 UTF-8 保存中文，cmd 在 GBK 代码页下解析错位，echo/注释被拆成乱码命令
  （日志出现 `'et'`、`'oto'` 等碎片，甚至误执行了文本中的 install.bat 字样）。
  修复：两个 bat 改为 **GBK + CRLF** 编码保存，去掉 `chcp 65001`。
- 回归验证：install.bat 全流程通过；run.bat 启动的进程确认为 `.venv\Scripts\python.exe main.py`；
  venv 内引擎自测 14/14 通过。
- 顺带修正 wheel 选包逻辑：优先正式版，排除 a/b/rc 预发布（openpyxl 3.1.5、lxml 6.1.3 等）。
